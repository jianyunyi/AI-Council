# AI Council UI 重设计

## 目标

将现有基础控制台升级为可信赖的多智能体开发指挥台。用户应在首屏理解系统如何把多个模型的意见收敛为一个由人工批准、在受控工作区执行的行动。

## 视觉方向

- 受众是开发者与技术决策者；采用深石墨底色和单一青绿色强调色。
- 使用不对称双栏首屏。左侧说明产品价值与两个明确入口；右侧展示一个有语义的 CSS 3D 协商模型。
- 3D 模型以“需求核心、模型席位、人工批准、受控执行”为可读节点。旋转、连线与流体光晕仅表达信息收敛，不作为无意义装饰。
- 设计参数：`DESIGN_VARIANCE 7`、`MOTION_INTENSITY 6`、`VISUAL_DENSITY 4`。
- 不新增大型三维或动画依赖。以 React、语义 HTML 与原生 CSS 3D transform 实现，保持桌面 EXE 静态导出兼容。

## 布局

1. 顶部保留现有路由与导航含义，更新为紧凑的产品导航与运行状态提示。
2. 首页改为不对称首屏：价值主张、任务入口与工作区入口位于左侧；动态协商场景与清晰的流程说明位于右侧。
3. 本地服务状态继续保留真实数据和现有控制，仅采用更清晰的层级、加载、空态及错误样式。
4. Provider、工作区、任务创建与任务查看页面继续使用既有字段、路由和 API；全局令牌、表单和反馈样式统一升级。

## 动效与无障碍

- 流体背景、节点环绕、能量连线使用慢速 CSS 动画，并限定在首屏视觉组件中。
- `prefers-reduced-motion: reduce` 时关闭旋转、脉冲和位移，仅展示稳定的流程图。
- 3D 场景提供等价的可见文本标签与流程列表；不以颜色作为唯一状态表达。
- 保持键盘焦点、可读对比度及移动端单列降级；不修改路由、导航名称或表单字段顺序。

## 验收

- 首页在桌面端展示可识别的 3D 多智能体协商流程和流体动效。
- 移动端不发生横向溢出，视觉内容可读并降级为单列。
- 减少动态效果偏好下没有持续运动。
- 真实服务状态、工作区与任务功能保持可用；现有 API 和桌面静态导出通过。
