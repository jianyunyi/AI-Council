# AI Council 协商钟塔全局 UI 设计

## 目标

以“协商钟塔”替换当前青绿色轨道风格，让 AI Council 在首屏直观呈现多模型提案、审阅、裁决、人工批准与受控执行的层级关系；同时让 Provider、工作区、任务、账户和 RBAC 页面成为同一套高效率工作台，而非营销页面的延伸。

## 范围与信息架构

- 首页采用三栏首屏：左侧命令栏（价值、创建任务、选择工作区）、中央透明协商塔（网页内 Remotion 演示）、右侧证据轨（提案、互审、裁决、批准、执行）。
- 顶部导航改为紧凑的“控制台索引”，突出当前会话与权限，而不改变任何路由、授权判断或文案含义。
- 操作页面统一为“状态带 + 内容面 + 证据/帮助区”：任务页强调状态、SSE 时间线、执行计划与批准；创建任务、Provider、工作区、登录、账户及用户管理保留全部字段和流程，只更新层级、布局和反馈。
- 不改变 REST、SSE、RBAC、桌面桥接、表单提交顺序或现有测试所依赖的语义文本。

## 视觉系统

- 色彩：蓝黑 `#1b2731` 为主场，陶土橙 `#c76f38` 仅表示批准/当前关键状态，骨白 `#e7d6b0` 用于高对比内容，矿物青 `#83a7a1` 用于辅助状态。错误与成功拥有独立、可读的颜色与文字标签。
- 材质：细密网格、透明层、轻微颗粒与压印状态带；不使用渐变玻璃卡堆、荧光描边或无意义粒子。
- 形态：方正或微小圆角的层级面板，固定刻度、编号和状态带替代大面积圆角卡片。
- 排版：以可本地回退的中文工作字体为正文；展示文字仅在首页使用有明确个性的窄体/结构化标题，不依赖运行时外网字体。

## Remotion 协商演示

- 在 `web` 中以精确锁定版本的 `@remotion/player` 嵌入 React 组件；不要引入视频渲染、音频、云服务或离线导出依赖。
- 新建纯展示 Composition：30 fps、约 12 秒、无音频、循环播放。五个已知阶段逐层构筑，当前阶段以陶土橙状态带固定；数据为明确标记的示例，不伪造模型调用、成本或成功率。
- 用户减少动态偏好时，渲染同等信息的静态塔、阶段列表和文本说明；演示不能成为理解流程的唯一方式。
- Player 不抢占键盘、不开启自动声音；如果浏览器阻止自动播放，首帧仍是完整可读的协商状态。

## 动效与三维边界

- 3D 只在首页协商塔与少量状态转换中使用，采用 Remotion 的二维层级、透视和时间轴，不加载 WebGL/Three.js。
- 流体感来自一条有限的、表示“证据收敛”的信号流；禁止全页浮动粒子、持续晃动或任何影响表单与表格阅读的运动。
- 任务页仅对新增 SSE 事件执行一次进入提示；批准、执行、验证为离散状态变化，不能用模糊过渡掩盖真实状态。

## 响应式、可访问性与性能

- `<=800px` 时三栏首屏重排为命令栏、塔、证据轨；演示缩短但保留静态阶段说明，导航可水平访问且不截断。
- 保持语义标题、表单标签、状态 `role`、可见焦点、44px 触控尺寸和非颜色状态文本；`prefers-reduced-motion` 停止所有非必要动画。
- 首屏演示应按需加载，页面其余部分不等待它。Remotion 组件、CSS 动画与图层数量必须在现有 Next 静态导出/桌面壳下工作。

## 验收

1. 首页在 1440px 与 390px 下均能识别“协商 → 人工批准 → 受控执行”，且无横向溢出。
2. 首页可见 Remotion 协商演示；禁用动态效果时仍有等价静态文本与阶段说明。
3. 所有现有 Web 路由、表单、RBAC 导航、任务批准执行和桌面控制保持可用。
4. Web Vitest、Next 构建、Playwright E2E 通过；设计检测、桌面与移动截图审查无未处理的关键缺陷。
5. 完成后由 Impeccable 记录 `DESIGN.md`，并对改动目标运行一次机械检测与独立设计审查。
